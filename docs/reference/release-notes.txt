0.6.0 — the blur was never running.

Check the version first: long-press the app icon, App info. It must read
0.6.0.

Ryan spotted it from one screenshot: the word COLLECTED was perfectly sharp
through the nav bar. At 20dp of blur that word should be an unreadable smear.
It was not blurred at all, so the bar was never frosted glass — it was a
transparent tinted shape with a lit edge, and every number tuned on top of it
across the last five builds was paint on a window.

The cause. A blur belongs to a layer, and it only happens when that layer is
drawn to a canvas. The blur was attached to the layer that records the screen,
which is never drawn to a canvas directly — it is only ever copied inside
another layer. The layer that does reach the screen had its effect set from
the refraction shader alone, and that shader needs Android 13; below it, the
value is nothing. So the pane drew a raw, sharp copy of whatever was behind
it.

Both effects are now on the layer that reaches the screen, chained, so the
frost happens first and the refraction bends the frosted result.

**The one thing to check.** Scroll Home so a word passes under the nav bar. If
it goes soft and unreadable, the glass is real. If you can still read it, the
blur is still not running and nothing else about the material is worth
discussing until it is.

One honest limit, unchanged. This material is a lens: it has almost no
substance of its own and everything it shows is what lies behind it, blurred
and saturated. The demo looks the way it does because it sits on a busy colour
photograph. Our ground is near-black and flat, so over empty background the
glass will always be quiet. Where it should now look right is over real
content — the nav bar with the parcel cards or the cabinet render running
under it.
